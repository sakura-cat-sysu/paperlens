# 分析流程与证据边界

```text
保存 PDF → 按物理页解析 → 拆解问题并建立任务清单
         → 每篇提取最多 6 条原子观点 → 程序核对每条引文
         → 仅传递全部引文匹配的观点 → 逐项回答与跨文献比较
         → 核对观点 ID、结论类型和任务覆盖 → 保存报告或未完成草稿
```

- 每篇最多 10 MiB、50 页、100,000 个提取字符，问题最多 2,000 字符；超限拒绝，不截断。
- 空白、损坏、加密、图片扫描件或明显编码异常会提示原因，不执行 OCR。双栏、图表、公式可能影响抽取顺序。
- 引文校验只忽略空白和换行，必须在指定物理页存在。不做大小写、标点或模糊匹配，少于 8 个非空白字符不作为可靠匹配。
- 任意一条引文失败，整条观点与解释标为待复核，不进入综合分析。匹配片段可供人工查看，不代表整条观点通过。
- 综合结论与逐项回答关联真实观点 ID，未知 ID 或被冻结观点的判断被隐藏。
- 共识、机制差异、结论冲突和差异原因至少关联两篇文献。方法与任务差异不冒充可比条件下的结论冲突。
- 判断分为论文报告、证据推导 / 假设、拟议方案。方案引用说明设计依据，不表示原论文已验证新方案。
- 问题拆为逐项任务，缺失、空回答、无效来源等显示草稿。适用限制、阈值待校准、方案待实证与真正漏答分开。
- 完成状态只检查结构和来源，不能自动认证科学正确性、语义支持或所有遗漏。原文存在不等于模型解释正确。
- 问题、文件名与文献都是不可信输入，Prompt 要求不执行其内嵌指令；界面以 React 文本渲染，不执行模型返回的 HTML / Markdown 链接或图片。

正常 2 篇文献为 4 次模型请求，3 篇为 5 次，包含问题拆解。支持 Chat Completions、Responses 和 Anthropic Messages；各协议在拆解、单篇阶段最多输出 4,096 tokens，综合阶段最多输出 8,192 tokens。

`OPENAI_STREAM=true` 时逐块接收上游 SSE；普通 JSON 和 SSE 按实际响应识别。只提取正文，完整生成后再执行原有校验和保存阶段检查点。流中错误、输出长度截断或缺少结束标志时，保留之前完成的阶段，不接受当前的部分回答。页面继续通过现有任务事件显示阶段进度。

每个阶段结构错误最多格式修复一次；SDK 自动重试关闭，连接与读取超时默认 60 秒（流式读取为等待下一数据块的超时）。只有 HTTP 400 / 422 明确提示不支持 Chat 的 `max_completion_tokens` 或必须流式时，才调整对应参数后重新请求，最多两次兼容调整。鉴权、额度、网络等其他错误不自动重试；引文不匹配不触发收费修复。协议变化隔离检查点，默认 Chat 协议保留已有检查点，流式开关不影响复用。

草稿续试只重新生成综合回答，失败续试复用已保存阶段。已完成报告不能重复提交续试；改变问题或文献时创建新任务。相同提交 UUID 返回原任务，浏览器普通重绘与阅读不会调用模型。

文件和结果在本版本持久保存，与原 Streamlit V0 的仅会话保存行为不同。用户在创建分析时会看到保存范围与模型发送说明，删除的快照边界在文献和报告确认框中明确展示。

既有真实 DeepSeek 验证发生在 V0，已证明原核心可调用服务，但不能替代新架构线上验收。本轮完整浏览器测试使用合成文献与本机合成模型，不访问真实模型或私人论文。
